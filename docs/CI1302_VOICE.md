# CI1302 语音接入 RK3576

本次以 Docs/妮妮小车_命令词播报词协议列表.xlsx 为唯一协议来源，配置文件保存源文件SHA256。代码已经接入，尚未连接、烧录或部署实车。

## 接线

采用用户确认的5V TTL语音模块，通过独立USB-TTL连接RK3576 USB主机口。选择真正支持5V TX/RX信号电平的适配器；部分适配器的5V跳线只切换VCC，不能代表RX耐压或TX电平。

|USB-TTL / 电源|语音模块|
|---|---|
|USB插头|连接RK3576 USB主机口|
|TXD|UART0_RX|
|RXD|UART0_TX|
|GND|GND，与模块供电地共地|
|稳定5V电源正极|模块5V/VCC|

不要把5V UART接到RK3576排针；不要使用RS232电平转换器；不要与F407或雷达共用串口。
若模块已经独立供电，USB-TTL的VCC悬空，只接TX、RX、GND。不要并联两个5V供电输出。
建议模块独立稳定5V、至少500mA供电能力。喇叭与麦克风仍接语音模块，不接RK音频口。
SOP示例CI-D02GS01J官方资料中，接口1为5V、2为GND、3为UART_TX、4为UART_RX；只有实物确认为该板型才能按此脚号接线，其余型号按丝印信号名连接。
官方参考：https://document.chipintelli.com/en/硬件开发/模块数据手册/CI130X系列/CI-D0XGS01J模块数据手册/

## 语音模块配置

导入最终Excel烧录对应固件；业务串口UART0、9600、8N1、自定义协议。调试打印不要混入UART0。
妮妮发送 BB 01 00 66；回到基站发送 BB 01 01 66；回到起点发送 BB 01 02 66。
48条被动播报使用Excel的AA开头协议。必须发送原始二进制，不是带空格的ASCII文本。
唤醒后15秒内接受一条返航命令，每条运动请求需要一次唤醒。模块内的唤醒保持时间也设为15秒。

## 部署和固定串口

修改位于现有 RK3576_deploy/rk3576_footbath_ws_source。一键部署脚本当前读取该目录，因此能够带上本次修改；本次不需要修改F407固件。
如果使用之前交付的源码压缩包，它不包含这次语音功能。使用当前源码目录或本次新压缩包。

在RK终端插入专用USB-TTL前后比较：

```bash
ls -l /dev/serial/by-id/
ls -l /dev/serial/by-path/
```

找出新增的语音适配器，使用完整稳定路径；不要根据ttyUSB0编号猜测，也不要选择底盘或雷达设备。
在当前工作区重新编译并安装后，先用播报测试模式配置（把下面路径替换为实物适配器）：

```bash
sudo bash /home/sky/rk3576_footbath_ws/scripts/configure_voice.sh /dev/serial/by-id/实际语音适配器名称 0
```

该脚本备份并更新 /etc/footbath/mobile.env，不会主动重启服务。结束当前任务并确认小车停车后：

```bash
sudo systemctl restart footbath-mobile
journalctl -u footbath-mobile -n 80 --no-pager
```

完成播报和唤醒检查后，再把配置脚本最后的0改为1执行，并在空闲停车时重启服务，以启用语音返航。
服务已有dialout组权限。未配置设备时默认仅尝试 /dev/footbath_voice，不自动扫描端口、不打开底盘或雷达。
FOOTBATH_VOICE_ENABLED=0完全关闭；FOOTBATH_VOICE_CONTROL=0只播报；FOOTBATH_VOICE_PORT指定设备。

## 行为与边界

- 网页仍负责选择地图、启动建图/导航并确认定位。语音不能在空闲状态自行加载未知地图。
- 返回基站复用当前地图绑定的基站和现有停靠流程。无有效基站时拒绝。
- 导航时最近出发点在新目标被接受时提交，取发送该任务前已静止且定位有效的位置；正常50cm出站前的位置不会被出站后覆盖。运动中切换目标无法证明新出发位姿时，该次起点无效，不沿用旧起点。
- 导航回起点复用普通Nav2目标与台阶恢复，先取消旧目标、确认动作结束和停车，不执行基站倒车停靠。
- 建图回起点使用本次建图开始前记录的位置，先保存地图、切定位，再返回该点；禁用基站对齐倒车。地图绑定的基站记录不改写。
- 最近出发点仅本次运行会话有效。更换地图、重新加载会话或服务重启后清除，防止把旧地图坐标当作当前起点。
- 故障、手动接管、危险恢复、定位失效或数据过期时，语音不能解除保护。
- 播报按状态变化发送，旧排队提示在任务切换时丢弃；无播放完成ACK，按字数估算间隔，不保证打断正在播放的语音。声学回授和模块打断策略须实测。
- “没有可通行路径”仅在导航结果提供明确无路径原因时播报；Humble未提供细分原因时播报通用导航失败，不猜测原因。
- “正在选择目标”要求探索器实际发布选点阶段、无活动导航目标且停车等待超过3秒。短暂停留不播报。
- 未连接语音设备不影响原有导航；连接中断不重发旧控制命令，已接受任务仍由现有安全监督器负责。

## 首次验收

1. 先关闭电机动力，在只播报模式验证启动、加载地图、定位提示；说妮妮确认模块确实发送BB 01 00 66。
2. 串口线路错误或波特率错误先排查，不能把收到任意字节当作控制命令。断开重接后不得执行旧命令。
3. 启用语音控制后，在空旷区域低速验证妮妮→回到基站，检查最终停靠后才播报完成。
4. 从已知位置发起普通导航，到另一点后说妮妮→回到起点，应回最近出发点而非基站或AMCL手动初始化点。
5. 建图时分别检查回基站和回起点；回起点不能执行最后的基站倒车流程。
6. 验证未唤醒、超过15秒、重复命令、手动接管和传感器异常时不启动新的返航；网页取消始终有效。
