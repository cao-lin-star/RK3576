# RK3576 与 STM32F407 接线表

> 适用硬件：野火 LubanCat-3IO（RK3576，8 GB + 64 GB）、野火 STM32F407ZGT6 霸天虎 V2、双 RPLIDAR C1、双 IBT-2、双 TOFSense-M S、HC-SR04/CS100A、PS2 接收器。
> 基线日期：2026-08-31。本文按当前 `.ioc`、生成源码、板级配置、udev 规则及 LubanCat-3IO 原理图整理。

## 1. 必须先遵守的电气规则

1. RK3576 和 STM32F407 的 GPIO/UART 都按 **3.3 V TTL** 使用，不能接 RS-232 电平。
2. RK 与 F407 的正式通信只接 `TX`、`RX`、`GND`，**不互接 3.3 V 或 5 V**。
3. RK 使用独立稳定 12 V 电源；两块 IBT-2 的 `B+ / B-` 使用独立 24 V 动力电源；24 V 严禁进入开发板逻辑电源引脚。
4. F407、RK UART、两块 IBT-2 逻辑地、编码器、ToF、超声波和其他传感器必须共信号地。电机大电流回路采用星形回地，避免电流经过串口/传感器地线。
5. 所有接线都在断电状态完成。首次上电关闭 24 V，并让车轮可靠悬空。

## 2. RK3576 与 F407 正式 UART 链路

| 信号 | STM32F407 端 | LubanCat-3IO 端 | 方向 | 固定配置 |
|---|---|---|---|---|
| F407 → RK 数据 | `PA9 / USART1_TX` | J32 物理 3 脚，复用为 `UART3_RX_M0` | PA9 → pin 3 | 115200 8N1 |
| RK → F407 数据 | `PA10 / USART1_RX` | J32 物理 5 脚，复用为 `UART3_TX_M0` | pin 5 → PA10 | 115200 8N1 |
| 信号地 | 任一可靠 `GND` | J32 物理 6 脚 `GND` | 双向参考地 | 必须连接 |
| 电源 | 不接 | J32 pin 1/2 的 3.3 V/5 V 不接 F407 | 禁止 | 两板独立供电 |

固定协议为：`AA 55` 帧头、协议 v1、多字节字段小端、`CRC16-CCITT-FALSE`、无硬件流控。F407 对 RK 命令保留最终 500 ms 超时停车保护。

### 2.1 UART3_M0 设备树复用

J32 pin 3/5 在底板原理图中默认网名是 `I2C7_M1`，必须在 RK 启用 UART3_M0 overlay，且不能同时启用 `i2c7-m1`、`uart3-m1` 或 `RS485-1`：

```text
#dtoverlay=/dtb/overlay/rk3576-lubancat-i2c7-m1-overlay.dtbo
dtoverlay=/dtb/overlay/rk3576-lubancat-uart3-m0-overlay.dtbo
#dtoverlay=/dtb/overlay/rk3576-lubancat-uart3-m1-overlay.dtbo
#dtoverlay=/dtb/overlay/rk3576-lubancat-3io-rs485-1-overlay.dtbo
```

重启 RK 后检查：

```bash
ls -l /dev/ttyS3
readlink -f /dev/footbath_stm32
```

正确结果为 `/dev/footbath_stm32 -> /dev/ttyS3`。应用层始终打开 `/dev/footbath_stm32`，规则来源是 `deploy/udev/99-footbath-uart3-m0.rules`。

### 2.2 必须排除的 PA9/PA10 冲突

- 移除或隔离霸天虎 V2 板载 CH340 与 PA9/PA10 的跳帽。
- fireDAP 的串口 TX/RX 不接 PA9/PA10；fireDAP 只做 SWD。
- 禁止同时让 RK TX、板载 CH340 TX 或其他 USB-TTL TX 驱动 PA10。
- USART1 是二进制正式链路，不能用 `echo`、minicom 或 ASCII 调试命令直接写入。

## 3. RK3576 的 USB 设备分配

| 设备 | 推荐物理接口 | 稳定设备名/识别方式 | 能否换 RK USB 插座 | 说明 |
|---|---|---|---|---|
| 高位 RPLIDAR C1 | 一个 USB3.0 Type-A | `/dev/footbath_lidar_high`；CP2102N 序列 `84fa76bdff1df111ae35bde40f0f12f8` | 可以 | C1 是 USB2 设备，插 USB3 正常；实体高位雷达身份不能与低位交换 |
| 低位 RPLIDAR C1 | 另一个 USB3.0 Type-A | `/dev/footbath_lidar_low`；CP2102N 序列 `14c5c9c4ff1df11186b7c4e40f0f12f8` | 可以 | 不接无源 Hub；udev 按唯一序列区分高低位 |
| UART4 独立 USB-TTL | 一个 USB2.0 Type-A | `/dev/footbath_chassis_debug`；VID:PID `0843:5740`，序列 `FX2348N` | 可以 | 仅 ASCII 日志/PID 调试，与正式 AA55 链路分开 |
| fireDAP/ST-Link | 余下 USB2.0 Type-A，需要烧录时接 | OpenOCD/调试器枚举 | 可以 | 只做 SWD；日常运行可拔除 |

软件身份由设备唯一序列号确定，不依赖 `/dev/ttyUSB0`、`ttyUSB1` 的枚举顺序。因此 USB 插座可换，但两台实体 C1 的安装位置不能互换。如果以后更换为无唯一序列号的 USB 转串口模块，必须重新建立基于 `ID_PATH` 的规则并固定物理插座。

## 4. fireDAP/ST-Link 与 UART4 调试接线

### 4.1 fireDAP/ST-Link（只做烧录和调试）

| 调试器端 | F407 端 | 备注 |
|---|---|---|
| SWDIO | `PA13 / SWDIO` | 固定 |
| SWCLK | `PA14 / SWCLK` | 固定 |
| NRST | `NRST` | 推荐连接，便于可靠复位和烧录 |
| VTref | F407 3.3 V 参考 | 仅电平参考，不用它给整板供电 |
| GND | F407 GND | 必须共地 |
| TX/RX | 不接 | fireDAP 不再兼任串口 |

### 4.2 独立 UART4 USB-TTL（ASCII 调试）

| USB-TTL 端 | F407 端 | 配置 |
|---|---|---|
| TX | `PC11 / UART4_RX` | 115200 8N1，3.3 V TTL |
| RX | `PC10 / UART4_TX` | 115200 8N1，3.3 V TTL |
| GND | F407 GND | 必须连接 |
| VCC | 不接 | 两端独立供电 |

PC10/PC11 与开发板 SD 卡 DAT2/DAT3 复用，使用 UART4 调试时不能插 SD 卡。

## 5. F407 完整外设接线

| 模块/功能 | F407 引脚 | 模块端 | 速率/电平 | 备注 |
|---|---|---|---|---|
| 左 IBT-2 | `PE9 TIM1_CH1` | RPWM | 20 kHz、3.3 V PWM | 左轮一个方向 |
| 左 IBT-2 | `PE11 TIM1_CH2` | LPWM | 20 kHz、3.3 V PWM | 左轮另一方向 |
| 左 IBT-2 | `PE8` | R_EN 与 L_EN 并接 | 3.3 V GPIO | 低电平禁能，不能只接一个 EN |
| 右 IBT-2 | `PE13 TIM1_CH3` | RPWM | 20 kHz、3.3 V PWM | 右轮一个方向 |
| 右 IBT-2 | `PE14 TIM1_CH4` | LPWM | 20 kHz、3.3 V PWM | 右轮另一方向 |
| 右 IBT-2 | `PE10` | R_EN 与 L_EN 并接 | 3.3 V GPIO | 低电平禁能 |
| 左编码器 | `PA15 TIM2_CH1` / `PB3 TIM2_CH2` | A / B | AB 正交 | 建议编码器用 3.3 V 供电；17×51×4=3468 count/rev |
| 右编码器 | `PB4 TIM3_CH1` / `PB5 TIM3_CH2` | A / B | AB 正交 | 同上 |
| 左 TOFSense-M S | `PD6 USART2_RX` / `PD5 USART2_TX` | TX / RX | 921600 8N1 | 主动数据由模块 TX 进入 PD6；PD5 用于配置 |
| 右 TOFSense-M S | `PD9 USART3_RX` / `PD8 USART3_TX` | TX / RX | 921600 8N1 | 主动数据由模块 TX 进入 PD9 |
| HC-SR04/CS100A | `PC0` / `PB6 TIM4_CH1` | Trig / Echo | 12 μs 触发；Echo 输入捕获 | Echo 若为 5 V，进入 PB6 前必须降到 3.3 V |
| 板载 MPU6050 | `PB8 I2C1_SCL` / `PB9 I2C1_SDA` | 板载 | I2C 100 kHz，地址 0x68 | 已使用板载器件，不并联同地址 GY-521 |
| PS2 接收器 | `PA4/PA5/PA6/PA7` | DATA/CMD/ATT/CLK | 3.3 V 软件时序 | 接收器使用 3.3 V；顺序不可交换 |
| 急停输入 | `PG4` | 常闭触点到 GND | 内部上拉、低有效 | 软件立即停机；实体急停还应能切断动力 |
| 左/右红外预留 | `PG2/PG3` | 模块 DO | 内部上拉、低有效 | 当前仅预留，红外联锁关闭 |
| 状态灯 | `PF6` | 板载红 LED | 低有效 | 故障状态指示 |

IBT-2 的 `B+ / B-` 只接 24 V 动力电源，`M+ / M-` 接对应电机，`VCC / GND` 接逻辑 5 V和公共地。F407 只提供控制信号，不给电机供电。

## 6. 软件中使用的传感器安装位姿

坐标基准为车体旋转中心 `base_footprint`，X 向前、Y 向左、Z 向上。

| 设备 | 当前软件位姿 | 数据职责 |
|---|---|---|
| 高位 C1 | `(0.10, 0, 0.50) m`；驱动坐标补偿 yaw=π | `/scan_high`；SLAM、AMCL、Nav2 障碍层 |
| 低位 C1 | `(0.10, 0, 0.15) m`；驱动坐标补偿 yaw=π | `/scan_low_raw` → 前方 135° 过滤为 `/scan_low_front`；仅导航补盲 |
| MPU6050 | `(0, 0, 0.195) m`，X 前/Y 左 | `/imu/data_raw` |
| 左 ToF | `(0.155563, +0.155563, 0.15) m`，左前 45° | 左侧下视台阶检测 |
| 右 ToF | `(0.155563, -0.155563, 0.15) m`，右前 45° | 右侧下视台阶检测 |
| 正前超声波 | `(0.135, 0, 0.24) m`，水平 | F407 近障硬停、Nav2 局部层、疑似玻璃诊断 |

雷达外观箭头仍朝车头。yaw=π 是对 RPLIDAR C1 驱动发布角度方向的坐标补偿，不代表把雷达机械倒装。

## 7. 接线后静态验收

保持 24 V 关闭，在 RK 执行：

```bash
ls -l /dev/ttyS3 /dev/footbath_stm32 \
  /dev/footbath_lidar_high /dev/footbath_lidar_low
readlink -f /dev/footbath_stm32
udevadm info --query=property --name=/dev/footbath_lidar_high | grep ID_SERIAL_SHORT
udevadm info --query=property --name=/dev/footbath_lidar_low  | grep ID_SERIAL_SHORT
./scripts/check_hardware.sh
```

通过标准：

- `/dev/footbath_stm32` 指向 `/dev/ttyS3`。
- 两个雷达别名存在且序列号分别匹配高/低实体。
- PA9/PA10 无 CH340 或其他 TX 争用。
- 所有逻辑地导通，但 RK/F407 供电轨没有互接。
- 24 V 关闭时完成串口、编码器、传感器静态检查；通过后才进入轮子悬空短测。

权威源码位置：F407 的 `F407/Footbath_Chassis_F407.ioc`、`F407/Core/Inc/main.h`、`include/board_config.h`；RK 的 `deploy/udev/`、`src/rk3576_footbath_bringup/config/hardware.yaml` 和 `src/rk3576_footbath_base/config/serial_bridge.yaml`。
