# RK3576 编译、部署与系统镜像烧录流程

> 适用板卡：野火 LubanCat-3IO，RK3576，8 GB RAM + 64 GB eMMC。
> 适用系统：Ubuntu 22.04 Lite + ROS 2 Humble。
> Git 仓库：`https://github.com/cao-lin-star/RK3576.git`。
> 基线日期：2026-08-31。

## 1. 先区分“编译部署”和“烧录镜像”

| 操作 | 什么时候做 | 是否清空 eMMC | 使用工具 |
|---|---|---:|---|
| ROS 2 源码编译/部署 | 日常修改节点、参数、网页、launch 后 | 否 | Git、rosdep、colcon、systemd |
| RK 系统镜像烧录 | 首次装机、系统损坏或明确重装时 | **是** | Windows DriverAssistant + RKDevTool |
| STM32F407 固件烧录 | 修改底盘固件时 | 不影响 RK eMMC | fireDAP/ST-Link + Keil/OpenOCD |

日常修改 RK 程序只执行第 3～7 节，绝不能每次都重烧系统镜像。

## 2. 三个源码位置的职责

| 位置 | 架构/文件系统 | 用途 | 能否作为部署产物来源 |
|---|---|---|---|
| Windows Git 工作区 | `G:\work\ROS2\RK3576_deploy\rk3576_footbath_ws_source` | VS Code 编辑、Git 提交和推送 | 只提供源码 |
| WSL Ubuntu | x86_64 Linux | 可做语法检查和部分主机测试 | 不能把其 `build/install/log` 复制到 RK |
| RK3576 | ARM64 Linux ext4，`/home/sky/rk3576_footbath_ws` | 安装依赖、colcon 编译、运行 ROS 2 | **唯一正式运行位置** |

Git 只管理源码、配置、脚本和文档。`build/`、`install/`、`log/`、住宅地图、rosbag、真实 PIN 和密钥不进入仓库。

## 3. 新板首次安装源码

先确认 RK 能访问 GitHub，登录 RK 终端：

```bash
ssh sky@<RK_IP>
```

首次克隆：

```bash
cd /home/sky
git clone https://github.com/cao-lin-star/RK3576.git rk3576_footbath_ws
cd /home/sky/rk3576_footbath_ws
git branch --show-current
git remote -v
```

应显示分支 `main`，远端 `origin` 为本项目仓库。已经由 Git 克隆过的板端工作区使用：

```bash
cd /home/sky/rk3576_footbath_ws
git status --short
git pull --ff-only origin main
```

如果板端目录是历史手工复制版本，先停止服务并完整备份，不要直接运行 `git reset --hard`。应在旁路目录克隆、构建和验收后，再在现场维护窗口切换；运行地图要另外备份。

## 4. 安装 ROS 依赖和固定上游源码

```bash
cd /home/sky/rk3576_footbath_ws
sudo ./scripts/install_dependencies.sh
source /opt/ros/humble/setup.bash
vcs import src --skip-existing < dependencies.repos
```

说明：

- `dependencies.repos` 只导入固定提交的 `sllidar_ros2`。
- `src/m_explore_ros2` 已连同许可证和上游版本记录固定纳入本仓库，不再重复下载。
- 不把依赖改成浮动的 `main/master`，否则同一源码将无法稳定复现。

检查外部依赖版本：

```bash
cd /home/sky/rk3576_footbath_ws/src/sllidar_ros2
git rev-parse HEAD
# 预期：34300099fadfc772965962dec837bf436706188f
```

## 5. 在 RK3576 上编译

### 5.1 完整编译

```bash
cd /home/sky/rk3576_footbath_ws
./scripts/build.sh
```

脚本实际执行：

1. `source /opt/ros/humble/setup.bash`；
2. `rosdep install --from-paths src --ignore-src -r -y --skip-keys ydlidar`；
3. `colcon build --symlink-install`。

成功后必须看到 `build/`、`install/`、`log/` 三个目录，且命令退出码为 0。

### 5.2 只编译一个改动包

例如只修改手机网页/网关：

```bash
source /opt/ros/humble/setup.bash
cd /home/sky/rk3576_footbath_ws
colcon build --packages-select rk3576_footbath_mobile \
  --symlink-install --event-handlers console_direct+
```

如果该包依赖同一工作空间中的其他改动，改用：

```bash
colcon build --packages-up-to rk3576_footbath_mobile --symlink-install
```

### 5.3 任何新终端都要加载环境

```bash
source /opt/ros/humble/setup.bash
source /home/sky/rk3576_footbath_ws/install/setup.bash
```

可以加入 `~/.bashrc`，但排障时仍建议手工执行，以免误用旧工作空间。

## 6. 编译后的测试与合同检查

```bash
cd /home/sky/rk3576_footbath_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
colcon test --event-handlers console_direct+
colcon test-result --verbose
python3 scripts/validate_phase1_contract.py
```

通过标准：

- `colcon test-result` 没有失败测试；
- 合同检查退出码为 0；
- 不存在从 `/cmd_vel` 绕过安全仲裁直接写 STM32 的路径；
- 高位雷达仍是 SLAM/AMCL 唯一激光输入，低位雷达只进入导航障碍层；
- F407 正式串口仍为 `/dev/footbath_stm32`。

如果测试失败，不要重启生产服务；先保留旧版本运行。

## 7. UART3、udev 与系统服务部署

### 7.1 首次启用 UART3_M0

确认 overlay 存在并备份启动配置：

```bash
test -e /boot/dtb/overlay/rk3576-lubancat-uart3-m0-overlay.dtbo
readlink -f /boot/uEnv/uEnv.txt
sudo cp -aL /boot/uEnv/uEnv.txt \
  /boot/uEnv/uEnv.txt.bak_before_uart3m0_$(date +%Y%m%d_%H%M%S)
sudo nano /boot/uEnv/uEnv.txt
```

确保只有 UART3_M0 启用：

```text
#dtoverlay=/dtb/overlay/rk3576-lubancat-i2c7-m1-overlay.dtbo
dtoverlay=/dtb/overlay/rk3576-lubancat-uart3-m0-overlay.dtbo
#dtoverlay=/dtb/overlay/rk3576-lubancat-uart3-m1-overlay.dtbo
#dtoverlay=/dtb/overlay/rk3576-lubancat-3io-rs485-1-overlay.dtbo
```

保存后：

```bash
sync
sudo reboot
```

重新登录并检查：

```bash
ls -l /dev/ttyS3
```

### 7.2 安装稳定设备名和备用固定模式服务

先插好两只 C1，并确认 F407 逻辑电已开启；电机 24 V仍关闭：

```bash
cd /home/sky/rk3576_footbath_ws
sudo ./scripts/install_systemd.sh
readlink -f /dev/footbath_stm32
ls -l /dev/footbath_lidar_high /dev/footbath_lidar_low
./scripts/check_hardware.sh
```

`/dev/footbath_stm32` 必须指向 `/dev/ttyS3`。该脚本同时安装 `rk3576-footbath.service`，但它只是固定模式备用入口。

### 7.3 安装当前生产入口：手机网关

```bash
cd /home/sky/rk3576_footbath_ws
sudo bash \
  src/rk3576_footbath_mobile/scripts/install_mobile_gateway.sh sky
```

首次安装会要求设置至少 6 位手机控制 PIN，盐和哈希只保存到 `/etc/footbath/mobile.env`，不能提交 Git。脚本会停用 `rk3576-footbath.service`，启用并重启 `footbath-mobile.service`。

当前生产模式只能保留一个总入口：

```bash
systemctl is-enabled footbath-mobile.service
systemctl is-active footbath-mobile.service
systemctl is-enabled rk3576-footbath.service || true
```

预期手机网关为 `enabled/active`，备用固定模式服务为 disabled。手机网页的短暂断连只约束手动遥控；已经启动的自动建图和自动导航由 RK 本地监督器继续维持，网页急停、传感器硬停和 F407 500 ms 最终保护仍生效。

### 7.4 可选远程调试/Foxglove

已有 SSH 公钥时执行：

```bash
sudo bash \
  src/rk3576_footbath_remote/scripts/install_remote_debug.sh \
  --user sky \
  --public-key /path/to/id_ed25519.pub \
  --enable-visualization
```

Foxglove 服务只监听本机 `127.0.0.1:8765`，电脑通过 SSH 端口转发访问，不直接暴露到局域网或公网。

## 8. 每次源码更新后的标准发布流程

Windows VS Code 中完成修改、测试、提交并推送后，在 RK 执行：

```bash
ssh sky@<RK_IP>
cd /home/sky/rk3576_footbath_ws
git status --short
git pull --ff-only origin main
./scripts/build.sh
source install/setup.bash
colcon test --event-handlers console_direct+
colcon test-result --verbose
python3 scripts/validate_phase1_contract.py
sudo systemctl restart footbath-mobile.service
systemctl --no-pager --full status footbath-mobile.service
```

发布后检查：

```bash
journalctl -u footbath-mobile.service -n 100 --no-pager
ros2 node list
ros2 topic list | sort
ros2 topic hz /scan_high
ros2 topic hz /scan_low_front
ros2 topic hz /odom
```

运动前再确认：24 V 电源状态、急停、前方空间、传感器有效位和唯一命令源。编译成功不等于允许无人值守运动。

## 9. Windows 烧录 Ubuntu 22.04 Lite 到 eMMC

这一节会擦除 64 GB eMMC，只在首次安装或系统恢复时使用。

### 9.1 已确认镜像和工具

```text
镜像：lubancat-rk3576-ubuntu22.04-lite-20260424_update.img
系统：Ubuntu 22.04 Jammy Lite
MD5：972172956504e98b1ffe2beb4c3d5c6e
RKDevTool：v3.37（RK3576 必须使用 v3.30 或更高）
DriverAssistant：v5.13
```

Windows PowerShell 校验：

```powershell
Get-FileHash -Algorithm MD5 -LiteralPath \
  'D:\下载目录\lubancat-rk3576-ubuntu22.04-lite-20260424_update.img'
```

哈希不完全一致时禁止烧录。

### 9.2 烧录前物理状态

1. 关闭小车 24 V 电机电源。
2. 关闭 RK，拔掉 STM32、双雷达、USB-TTL、fireDAP 和其他 USB 外设。
3. 只保留 RK 独立 12 V 电源，以及电脑到 RK **OTG/烧录 Type-C** 的可靠数据线。
4. 不使用只能充电的 Type-C 线；不要通过 RK USB 给整车供电。
5. 准备好镜像、MD5 和稳定电脑电源，烧录中途不能休眠、拔线或断电。

### 9.3 安装驱动和进入 Loader

1. 运行 DriverAssistant 的 `DriverInstall.exe`。若存在旧 Rockchip 驱动，先在工具中卸载，再重新安装。
2. 打开 RKDevTool v3.37，进入“升级固件”页。
3. RK 断电，将电脑数据线接到 OTG Type-C。
4. 按住底板 `RECOVERY` 键，再接入 RK 独立 12 V 电源。
5. RKDevTool 显示“发现一个 LOADER 设备”后松开 `RECOVERY`。
6. 如果 Recovery 无法识别或 eMMC 系统严重损坏，才改用 `MASKROM` 键进入 MASKROM；正常升级优先 Loader。

### 9.4 写入镜像

1. 在“升级固件”页选择校验通过的 `*_update.img`。
2. 等待 RKDevTool 完成镜像解析。
3. 点击“升级”。
4. 等待进度完成并明确显示升级成功。
5. 烧录过程中禁止关闭 RKDevTool、拔 Type-C、断 12 V 或操作电机电源。
6. 成功后先正常断电，再拔 OTG 线，最后按普通供电方式启动。

### 9.5 第一次启动和系统核验

首次启动可能自动初始化并重启，等待 2～5 分钟。官方 Debug 串口参数为 1500000 8N1。首次登录后立即修改官方默认密码，再创建/核验 `sky` 用户和 SSH。

```bash
cat /etc/os-release
uname -a
dpkg --print-architecture
free -h
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS
ip -br address
```

通过标准：Ubuntu 22.04、`arm64/aarch64`、内存与 64 GB eMMC 容量合理，Rockchip 6.1.99 系列内核正常启动，网卡和 USB 可识别。

建议初始化：

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo hostnamectl set-hostname lubancat3-footbath
sudo usermod -aG sudo,dialout,video,render,plugdev sky
sudo apt update
sudo reboot
```

确认 `sky` 能 SSH 登录并执行 `sudo -v` 后，再做账户加固，避免提前锁死登录入口。

## 10. 常见故障速查

| 现象 | 首先检查 |
|---|---|
| 重启后没有 `/dev/ttyS3` | `/boot/uEnv/uEnv.txt` 是否只启用 uart3-m0；是否真正 reboot |
| `footbath_stm32` 指向 ttyACM/ttyUSB | 旧 fireDAP/USB-TTL udev 规则仍占用别名 |
| 两只 C1 高低互换 | 实体序列号与 `99-footbath-lidars.rules` 是否一致；不要依赖 ttyUSB 编号 |
| `colcon build` 在 Windows/WSL 成功但 RK 不能运行 | 架构不一致；删除板端旧 `build/install/log` 后在 RK ARM64 重新编译 |
| 手机模式反复回 idle | 查 `footbath-mobile.service` 日志；确认没有同时启用备用固定模式服务 |
| Foxglove 断连 | 先查 SSH 隧道和 `footbath-foxglove.service`，再查 ROS 话题；不要直接开放 8765 |
| 拉取后出现本地修改冲突 | 停止发布，不要 `reset --hard`；先保存 `git status`/`git diff` 并人工合并 |
| RKDevTool 找不到设备 | 数据线、OTG 口、Rockchip 驱动、Recovery 按键时序和独立 12 V |

## 11. 版本回退原则

每次发布前记录当前提交：

```bash
cd /home/sky/rk3576_footbath_ws
git rev-parse HEAD
```

如果新版本测试失败，先停止手机网关和运动电源，再切换到明确已验证的提交进行重新编译。不要复制旧机器的 `build/install/log` 进行回退；永远由目标提交的源码在 RK 本机重新构建。运行地图位于 `/home/sky/rk3576_footbath_ws/maps`，应独立备份，不随 Git 分支切换。
